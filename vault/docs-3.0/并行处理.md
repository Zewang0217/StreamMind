# Java并行处理技术完整笔记

## 一、Java并行处理核心概念

### 1.1 并行处理基础

- 并行处理 ：将任务分解为多个子任务，同时在多个CPU核心上执行，提高处理效率
- 并发 vs 并行 ：并发是指逻辑上的同时发生，并行是物理上的同时发生
- 线程安全 ：多线程环境下数据一致性和正确性保证

### 1.2 线程安全数据结构

- ConcurrentHashMap ：分段锁实现的线程安全哈希表
- CopyOnWriteArrayList ：读多写少场景的线程安全列表
- BlockingQueue ：线程安全的阻塞队列
- ConcurrentLinkedQueue ：无锁并发队列

## 二、本项目使用的并行处理技术

### 2.1 ThreadPoolExecutor线程池

```
private final ExecutorService executorService = new ThreadPoolExecutor(
        Runtime.getRuntime().availableProcessors() * 2, // 核心线程数
        Runtime.getRuntime().availableProcessors() * 4, // 最大线程数
        60L, TimeUnit.SECONDS,                          // 空闲线程超时时间
        new LinkedBlockingQueue<>(100),                // 工作队列
        new ThreadPoolExecutor.CallerRunsPolicy()      // 拒绝策略
);
```

- 参数调优原则 ：
    
    - 核心线程数 = CPU核心数 * 2（I/O密集型任务）
    - 最大线程数 = CPU核心数 * 4
    - 工作队列容量适中，防止内存溢出
    - 合理的拒绝策略确保系统稳定性

### 2.2 CompletableFuture异步编程

```
List<CompletableFuture<Void>> futures = feedsToFetch.stream()
        .map(feedConfig -> CompletableFuture.runAsync(
                () -> processFeedWithRetry(feedConfig, rssHubConfig.getUrl()),
                executorService))
        .collect(Collectors.toList());

// 等待所有任务完成
CompletableFuture.allOf(futures.toArray(new CompletableFuture[0])).join();
```

- 优势 ：非阻塞执行、链式调用、异常处理、组合操作
- 应用场景 ：并行执行相互独立的任务，等待所有任务完成后继续

### 2.3 Java Stream并行流

```
List<SocialMessage> messagesToSend = filteredItems.stream()
    .filter(item -> {
        // 去重逻辑
    })
    .map(item -> convertToSocialMessage(item, config))
    .collect(Collectors.toList());
```

- 并行流使用 ：只需将 stream() 改为 parallelStream()
- 注意事项 ：并行流使用ForkJoinPool，适合CPU密集型任务

## 三、未使用但重要的并行处理技术

### 3.1 ForkJoinPool分治框架

- 适用场景 ：大规模数据处理，可分解为小任务
- 使用示例 ：

```
ForkJoinPool forkJoinPool = new ForkJoinPool(
    Runtime.getRuntime().availableProcessors()
);

// 提交任务并获取结果
Integer result = forkJoinPool.invoke(new MyRecursiveTask(data));
```

- 核心类 ：
    
    - RecursiveTask<T> ：有返回值的递归任务
    - RecursiveAction ：无返回值的递归任务

### 3.2 CountDownLatch同步工具

- 适用场景 ：等待多个线程完成后再继续执行
- 使用示例 ：

```
CountDownLatch latch = new CountDownLatch(feedList.size());

for (RSSHubFeedConfig feed : feedList) {
    executorService.submit(() -> {
        try {
            processFeed(feed);
        } finally {
            latch.countDown();
        }
    });
}

// 等待所有线程完成
latch.await();
```

### 3.3 ParallelStream高级用法

- 自定义线程池 ：

```
ForkJoinPool customThreadPool = new ForkJoinPool(10);
List<Result> results = customThreadPool.submit(() ->
    items.parallelStream()
        .map(this::processItem)
        .collect(Collectors.toList())
).join();

```

- 流的并行度控制 ：

```
System.setProperty("java.util.concurrent.ForkJoinPool.common.parallelism", "8");
```

### 3.4 Reactive Programming响应式编程

- Spring WebFlux ：基于Reactor的响应式编程框架
- 使用示例 ：

```
// 并行处理多个API调用
Flux<RSSHubFeedConfig> feedFlux = Flux.fromIterable(feedsToFetch);
feedFlux.parallel()
    .runOn(Schedulers.parallel())
    .doOnNext(this::collectFeed)
    .sequential()
    .blockLast();
```

- 优势 ：非阻塞I/O、背压控制、资源利用率高

### 3.5 生产者-消费者模式

- 适用场景 ：处理大量异步任务的流水线模式
- 使用示例 ：

```
// 创建阻塞队列作为缓冲区
BlockingQueue<RSSHubFeedConfig> queue = new LinkedBlockingQueue<>(100);

// 启动消费者线程
for (int i = 0; i < 10; i++) {
    executorService.submit(() -> {
        while (!Thread.currentThread().isInterrupted()) {
            try {
                RSSHubFeedConfig feed = queue.take();
                collectFeed(feed, rssHubUrl);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                break;
            }
        }
    });
}

// 生产者添加任务
feedsToFetch.forEach(queue::offer);
```

## 四、并行处理最佳实践

### 4.1 性能优化要点

- 任务粒度 ：任务太小会增加调度开销，太大会导致并行度不足
- 避免共享状态 ：减少锁竞争，使用线程本地变量
- 合理使用异步 ：I/O密集型任务适合异步处理
- 监控与调优 ：使用JMX监控线程池状态

### 4.2 常见问题与解决方案

- 线程安全问题 ：使用线程安全集合、同步块或原子类
- 死锁 ：避免嵌套锁、使用tryLock设置超时
- 内存泄漏 ：确保线程池正确关闭，避免线程局部变量累积
- 资源耗尽 ：合理设置线程池大小，实现优雅降级

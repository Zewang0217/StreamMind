###  StreamMind 3.0 - AI 驱动的信息监控实战路线图


#### 核心架构流转

> **RSS 源** -> **Collector (采集+打标)** -> `[Topic: raw-rss]` -> **Analyzer (AI初筛 -> Jina全文 -> AI写作)** -> `[Topic: ai-articles]` -> **Consumer (落地存储/发布)**

---

#### 阶段一：基础设施升级 (Common & Collector)

**目标：** 让数据携带“分类”信息，并为 AI 引入做准备。

1. **Common 模块升级**
    
    - [ ] **依赖引入：** 在 `common/pom.xml` 中引入 `spring-ai-openai-spring-boot-starter` (为了统一管理版本)。
        
    - [ ] **DTO 扩展：** 修改 `SocialMessage` 或新建 `RssRawMessage`，增加 `category` (分类) 和 `contentFetchStatus` (内容抓取状态) 字段。
        
    - [ ] **新增 DTO：** 创建 `AiArticleMessage`，包含 `title`, `summary`, `fullMarkdownContent`, `generatedBlogWaitToPublish`。
        
2. **Collector Service 升级 (数据源头)**
    
    - [ ] **分类映射逻辑：** 修改 `RSSHubFeedConfig`，允许为每个 RSS 源配置一个 `category` (如：36kr -> TechNews, 少数派 -> Productivity)。
        
    - [ ] **采集逻辑优化：** 采集时不进行任何过滤，只负责将 RSS XML 转换为统一的 JSON 消息，带上 `category` 标签，发送至 Kafka `raw-rss-feeds`。
        

---

#### 阶段二：构建 AI 智能分析核心 (Stream Analyzer)

**目标：** 这是本次升级的核心，将原本的简单的流处理替换为 **AI Agent Pipeline**。 _建议直接在 `stream-analyzer` 服务中实现，暂时不需要 Kafka Streams 的复杂拓扑，使用简单的 `@KafkaListener` 即可，因为 AI 调用是阻塞的，简单的消费者模型更容易控制并发。_

**步骤清单：**

1. **引入 Spring AI**
    
    - 配置 `application.yml` 填入 DeepSeek 或 OpenAI 的 Key。
        
2. **实现 Pipeline Service (核心逻辑)**
    
    - 创建 `AiPipelineService.java`，包含三个步骤的方法：
        
    - **步骤 A (初筛 - Filter Agent):**
        
        - **Input:** 标题 + 描述
            
        - **Prompt:** “你是一个科技主编。请对这条新闻打分（0-10）。如果是仅仅是广告或无意义内容，打0分。如果是核心硬核技术或重大产品更新，打高分。只返回数字。”
            
        - **Logic:** 如果分数 < 7，直接丢弃 (Log记录)。
            
    - **步骤 B (全文抓取 - Fetcher Tool):**
        
        - **Logic:** 如果分数 >= 7，使用 Java `RestClient` 调用 `https://r.jina.ai/{url}`。
            
        - **Output:** 获取纯净的 Markdown 文本。
            
    - **步骤 C (深度写作 - Writer Agent):**
        
        - **Prompt:** “根据以下 Markdown 内容，为我写一篇博客文章。要求：1. 使用 Markdown 格式。2. 第一段通过 Emoji 吸引眼球。3. 总结三个核心技术点。4. 语气要像是一个资深开发者在分享。”
            
        - **Output:** 生成最终的文章内容。
            
3. **发送结果**
    
    - 将生成的文章封装进 `AiArticleMessage`，发送到 Kafka 新 Topic：`ai-generated-articles`。
        

---

#### 阶段三：落地与存储 (Consumer Service)

**目标：** 将 AI 写好的文章变成你博客的一部分。

1. **文件系统适配**
    
    - 在 `application.yml` 中配置一个本地路径：`blog.posts.path: /Users/yourname/my-blog/source/_posts` (假设你用的是 Hexo/Hugo)。
        
2. **消费者逻辑**
    
    - 监听 `ai-generated-articles` Topic。
        
    - 接收到消息后，创建一个 `.md` 文件。
        
    - **文件名：** `YYYY-MM-DD-{Slugized_Title}.md`
        
    - **文件内容：** 自动拼接 Front-matter (博客元数据) + AI 生成的内容。
        
    - _（可选）_ 自动执行 `git add . && git commit -m "Auto post"` (通过 Java `ProcessBuilder` 调用 shell)。

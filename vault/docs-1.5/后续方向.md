### 1. 关于信息源是否充足（目前仅微博/知乎/B站）

**结论：对于“垂直领域跟踪”，目前的信息源不仅“不充足”，而且“信噪比过低”。**

- **改进建议：** 你需要引入**“行业源头”**和**“技术前哨”**。
    
    - **对于 AI/技术领域：** 必须包含 GitHub Trending、Hacker News、Product Hunt、36Kr/少数派（国内科技媒体）、掘金/V2EX。
        
    - **对于生活/做饭领域：** 小红书（RSSHub 支持但反爬极严，可能需要自建实例）、豆瓣小组、YouTube 特定频道。
        

### 2. 核心难点：如何预测一个“我不知道的新概念”？（关键词从何而来？）

这是一个非常经典的**“爆发检测”（Burst Detection）**问题。你不需要预先知道“DeepSeek”这个词，而是通过统计学让系统告诉你“这个词异常了”。

**解决方案：全量分词 + 速度/加速度监测**

不要去统计你脑子里有的词（如“AI”、“模型”），而是统计**所有出现的名词**。

- **第一步：分词（Tokenizer）**
    
    - 每当 Crawler 抓取到一个新标题（例如：“DeepSeek V3 发布，性能超越 GPT-4”），使用 Java 的 NLP 库（推荐 **HanLP** 或 **jieba-java**）提取其中的**名词**和**实体**。
        
    - 提取结果：`[DeepSeek, V3, 性能, GPT-4]`。
        
- **第二步：滑动窗口统计（流处理）**
    
    - 利用你的 `stream` 模块（Kafka Streams）。
        
    - 建立一个时间窗口（比如 1 小时）。
        
    - 统计每个词出现的次数。
        
- **第三步：计算“加速度”（Trend Velocity）**
    
    - 如果 `DeepSeek` 在昨天 12:00-13:00 出现了 0 次。
        
    - 今天 12:00-13:00 出现了 50 次。
        
    - **增长率无穷大** -> **触发阈值** -> **这是一个新热词**。
        
    - **系统自动将其标记为“趋势”，并丢给 AI 去分析“这到底是什么东西”。**
        

### 3. 去重：MD5 还是 Redis？

**结论：这是两个维度的东西，你需要“Redis 存储 MD5”。**

- **MD5/SHA-256：** 是**算法**。用来把一篇 5000 字的文章压缩成一个 32 位的字符串（指纹），用于比对。
    
- **Redis：** 是**存储介质**。
    
    - 如果你只用 Java `HashMap` 存 MD5，服务一重启，所有历史记录全没了，你会重复抓取昨天的旧新闻，浪费 Token。
        
    - **必须引入 Redis。**
        

**最佳实践（SetNX 模式）：**

1. 计算文章标题+链接的 MD5：`hash = md5(title + link)`
    
2. 调用 Redis：`SETNX "dedup:social:" + hash, "1"`
    
3. 设置过期时间（TTL）：`EXPIRE "dedup:social:" + hash, 86400` (24小时)
    
    - 如果 Redis 返回 `1` (True)：说明是新消息 -> 处理。
        
    - 如果 Redis 返回 `0` (False)：说明处理过了 -> 丢弃。
        

**成本分析：** Redis 极其轻量，且你不需要持久化太久（通常新闻超过 3 天就不需要去重了，因为很少会有人重复发 3 天前的新闻），所以内存占用很小。
